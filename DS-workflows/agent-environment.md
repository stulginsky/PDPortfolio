# Agent Environment — старт среды для DS-проекта

Документ для подготовки проекта, в котором агент будет создавать, синхронизировать или использовать дизайн-систему.

## Минимальные доступы

Агенту нужны:

- доступ к репозиторию проекта;
- доступ к DS-документации проекта;
- доступ к Figma file через MCP или ссылку на node;
- возможность читать ключевые файлы кода;
- возможность запускать build/test/lint, если это требуется задачей;
- понимание технологического стека проекта.

## Figma MCP

Рекомендуемый вариант — remote Figma MCP.

Проверка готовности:

1. Figma plugin/connector установлен.
2. Агент видит Figma tools.
3. По ссылке на node агент может получить metadata.
4. По ссылке на node агент может получить screenshot.
5. Для компонентов агент может получить component metadata или design context.

Формат ссылки должен включать `node-id`, например:

```text
https://www.figma.com/design/<fileKey>/<fileName>?node-id=123-456
```

Если `node-id` нет, агент должен попросить node-specific link.

## Рекомендуемая структура DS-документации

```text
DS/
  DS.md

ds/
  brand-brief.md
  CONTRACT.md
  foundation.md
  components.md
```

В mono-repo или проекте с отдельным DS-репозиторием допустимо хранить `ds/` рядом с проектом. Главное — в проекте должна быть точка входа `DS/DS.md`, где указаны канонические источники.

## `DS/DS.md` как точка входа

`DS/DS.md` должен отвечать на вопросы:

- где лежит Figma file;
- какие frame/node являются каноническими;
- где лежат DS docs;
- где лежат данные/контент, влияющие на UI;
- где лежат токены в коде;
- какой порядок синхронизации перед UI-задачей;
- что нельзя дублировать в этом репозитории.

## Стартовый чеклист агента

Перед первой DS-задачей агент должен:

1. Прочитать `DS/DS.md`, если он есть.
2. Прочитать `CONTRACT.md`.
3. Прочитать `foundation.md`.
4. Прочитать `components.md`.
5. Открыть Figma node, указанный в задаче.
6. Определить стек проекта.
7. Найти token layer в коде.
8. Найти UI components в коде.
9. Проверить build/test команды.
10. Зафиксировать расхождения или подтвердить готовность.

## Если проект стартует с нуля

Создать минимальный пакет:

```text
DS/DS.md
ds/brand-brief.md
ds/CONTRACT.md
ds/foundation.md
ds/components.md
```

Затем выполнить `directive-01-create-ds-from-scratch.md`.

## Если проект уже существует

Сначала не переписывать UI. Нужно выполнить аудит:

1. собрать Figma/screens/code references;
2. извлечь повторяющиеся значения;
3. составить preliminary foundation;
4. отделить legacy от DS;
5. выполнить `directive-02-migrate-existing-design-to-ds.md`.

## Рабочий формат задачи

Хорошая DS-задача для агента содержит:

- ссылку на Figma frame/node;
- цель: создать, синхронизировать, перенести, проверить или расширить;
- путь к DS docs;
- путь к token layer в коде;
- ограничения: не менять legacy, не добавлять dependencies, сохранить visual parity и т.д.

Пример:

```text
Проверь экран Checkout по Figma node <link>.
DS docs лежат в ./ds.
Токены в app/assets/css/tokens.css.
Если нужен новый компонент, сначала обнови components.md.
```

## Definition of Ready

Среда готова к DS-работе, если:

- агент читает DS docs;
- агент читает Figma node;
- понятен источник правды;
- понятно, где token layer в коде;
- понятно, где UI components в коде;
- есть команда проверки проекта или явно сказано, что её нет.

## Write safety для Figma MCP

Для задач, которые меняют Figma:

- сначала согласовать markdown-описание результата;
- не выполнять write-вызов до апрува структуры;
- не завершать мутирующий вызов через `throw`;
- делать проверку отдельным read-only вызовом;
- после проверки запросить screenshot ключевой секции/frame;
- при создании UI-kit проверять, что узлы стали `COMPONENT` / `COMPONENT_SET`;
- при расширении UI-kit работать пакетами по 2-3 компонента.

Для задач, которые только индексируют DS:

- не менять Figma;
- не читать весь корень большого файла;
- читать Variables и верхний уровень Components;
- не заходить рекурсивно в instances.

## Агентный указатель

Если проект используется несколькими агентами или сессиями, добавить ссылку на DS contract в один из файлов:

- `AGENTS.md`, если проект ориентирован на Codex/agent workflow;
- `CLAUDE.md`, если проект уже использует Claude Code;
- `DS/DS.md`, если DS-точка входа уже является обязательной;
- `README.md`, если других агентных файлов нет.

Минимальное содержание:

```md
## Дизайн-система

Перед любой UI-задачей прочитать `ds/CONTRACT.md`, `ds/foundation.md`, `ds/components.md`.
Новый UI делается только через DS. Если нужного токена или компонента нет, сначала расширить DS.
```
